# 机器人强化学习平衡测试

战斗直接 import `src/data.js`、`src/engine.js`，不复制伤害、状态、角色或敌人结算规则。需要 Node.js 22 及以上，无额外 npm 依赖。

## 用法

```sh
# 冒烟：五个角色各 5 局（只输出 JSON 和逐角色结果文件）
node tools/bot/sim.mjs 5
# 单局重放：种子同时决定地图、流派、奖励和战斗随机数
SEED=123 node tools/bot/sim.mjs 1 hansong
# 不写文件；WEIGHTS 可以是 JSON 对象或 JSON 文件路径
NOWRITE=1 WEIGHTS='{"blockNeeded":18}' node tools/bot/sim.mjs 5 hansong
# 训练：分钟数包含搜索与预留验证预算；最后三组固定各 1000 局
node tools/bot/train.mjs hansong 55
```

PowerShell 使用 `$env:SEED='123'`、`$env:NOWRITE='1'` 设置环境变量后再运行命令。权重优先级：内置 W → `weights.json` 对应角色 → `WEIGHTS`；空对象表示使用默认值。模拟每回合至多出 25 张牌，至多打 60 回合。程序报错停止该局，记入 JSON，并使模拟进程返回非零状态。

## 策略与统计

每个角色有两个固定选牌方向：韩松狙击 / 冲锋枪和手枪；陈默留刀 / 流血；田守义怒 / 守；赵铁山爆破 / 工事；沈知秋侦明 / 伏击。种子奇偶均匀分配两种流派。机器人优先打档案箱押运者，其次攻击低血目标；仪式按鼓、铃、刀顺序出牌。根据缺口补防、能量预算内的估算斩杀伤害、角色资源和场面重新给出牌与按钮打分，侦明弃线索以触发效果。

地图采用 `game.js` 的六条路径、不交叉连线、章节固定层、节点权重和相邻特殊节点限制；候选连线用带种子的洗牌代替随机比较排序。机器人在可达节点中规划加强精英路线，隐藏地图时随机选路，不保证每局拿到三份情报。战斗奖励池/稀有度、缴获牌、口粮、背包掉率、商店价格、休息二选一、首领稀有牌及物品三选一、章间 50% 回血和口粮补给与游戏一致。三章全通且集齐情报才挑战 staff，不额外回血。

允许的简化仅在事件：等概率回复 8 生命、口粮 +2、从普通奖励三选一或随机随身物品，不执行剧情分支和拼图。初始进度为新局，不模拟玩家永久解锁。打法分数中的常数集中在 W；伤害估值只是决策特征，实际效果完全由引擎决定。机器人和事件模型会影响测得胜率，不能把它等同于真人胜率。

训练采用对称采样、前 1/4 对数加权、sigma ×0.97。候选在同代共用种子，最终留出种子 777—1776，原权重/均值/历史最佳各 1000 局；退步或同分保留原权重。分钟数是预算目标，最后验证必须跑完，机器较慢时可能超过输入时间；工作流有独立超时保护。

在 GitHub Actions 手动选择“机器人强化训练”或“机器人平衡测试”。默认训练 55 分钟，五角色并行；测试每角色 300 局。两项工作流只读取和提交 preview，使用同一个并发组避免相互覆盖；只接受五份完整产物。平衡测试即使出现游戏异常也会汇总已写出的报错上下文，流程仍标红。自动提交含 `[skip ci]`。

报告位于 `data/bot_train.md`、`data/bot_balance.md`；JSON 含种子、源提交、完整报错牌组与敌人信息。训练不自动启动；本地只需运行少量冒烟。
